# T-065 — «Enseñar»: permitir que el texto clave incluya el importe

- **Estado:** pendiente
- **Rama:** `codex/t-065`
- **Rama base:** `claude/fase-7-ampliaciones` (desde `main` tras la fusión del 2026-09-30)
- **Depende de:** T-058/T-059 (automatización aprendida)
- **Riesgo:** medio (motor de notificaciones, zona de control reforzado). **Sin cambios de Room.**
- **Tipo:** corrección de un fallo real

## Objetivo
El usuario (2026-09-30) intenta enseñar esta notificación de Trade Republic (título + cuerpo):
`CHANGLONET, S.L.` / `Gastaste 3,75 € en CHANGLONET, S.L.`
Marca como **texto clave** desde «Gastaste» hasta «en» y como **texto variable** «CHANGLONET,». La pantalla muestra «No se ha detectado un importe válido» y el botón Guardar queda deshabilitado. Además, la tarjeta de valores de la regla dice «Se aplican solo a  y tienen prioridad…» (hueco vacío).

Causa (localizada por Claude): `domain/notifications/NotificationTemplateEngine.kt`, `NotificationTemplateBuilder.build` busca el primer importe que **no se solape** ni con el rango clave ni con el variable. El texto clave es un único fragmento continuo (de la primera a la última palabra pulsada), así que «Gastaste … en» contiene el importe `3,75 €`, no queda ningún importe libre y se lanza la excepción. Marcar el texto que rodea al importe es lo natural, así que el motor debe aceptarlo.

## Decisiones ya cerradas
1. **El texto clave puede contener el importe.** Si el importe elegido queda dentro del rango clave, el rango clave se parte en `Literal(antes)` + `Amount` + `Literal(después)`; los trozos vacíos se omiten y los espacios se conservan como hasta ahora (el matcher ya los trata con `\s+`). Debe quedar al menos un literal no vacío (texto clave obligatorio).
2. **Qué importe se usa:** el mismo que la pantalla resalta (`NotificationAmountRecognizer.first(text)`, fichas rojas). Si ese importe se solapa con el **texto variable**, error «El texto variable no puede incluir el importe». Si el importe solo se solapa **parcialmente** con el rango clave (por ejemplo, la selección empieza o acaba dentro del importe), el rango clave se amplía para cubrir el importe completo antes de partirlo.
3. **Mensajes de error distintos:** sin importe en toda la notificación → «No se ha detectado ningún importe en la notificación»; importe dentro del texto variable → el mensaje del punto 2; solapamiento entre clave y variable → «El texto clave y el variable no pueden solaparse». Los mensajes se muestran como hasta ahora en la pantalla.
4. **Plantillas ya guardadas:** no cambian (el formato JSON de segmentos sigue igual; una plantilla `Literal, Amount, Literal, Variable` ya era representable). El matcher (`NotificationTemplateMatcher`) no debería necesitar cambios; si los necesita, justifícalo en el informe.
5. **Texto de la tarjeta de la regla:** cuando todavía no hay texto variable (o está vacío), `auto_rule_explanation` no debe mostrar un hueco: usa una cadena alternativa, «Se aplican solo al comercio, persona o activo marcado como texto variable y tienen prioridad sobre la estructura». Aplícalo en los tres usos de `auto_rule_explanation` de `ui/automation/AutomationScreens.kt`.
6. **Ayuda de la pantalla:** amplía `auto_selection_help`: «Pulsa la primera y la última palabra de cada fragmento. Puedes pulsar una sola palabra. El importe (en rojo) se detecta solo; el texto clave puede incluirlo.»
7. Textos en español; `docs/tasks/COMMON.md` obligatorio. Sin registrar el texto de las notificaciones en logs.

## Casos límite a cubrir
Clave «Gastaste … en» con el importe dentro (caso real); clave que termina justo antes del importe (comportamiento actual, sigue funcionando); clave con el importe al principio o al final del fragmento; selección que corta el importe; variable que contiene el importe; clave y variable solapadas; notificación sin importe; importe con `+`; varias cantidades en el texto.

## Tests obligatorios
- `NotificationTemplateBuilder` con el caso real exacto: plantilla resultante `[Literal("Gastaste "), Amount, Literal(" en "), Variable]`.
- Con esa plantilla, `NotificationTemplateMatcher.match` sobre `MERCADONA` / `Gastaste 12,40 € en MERCADONA` devuelve variable `MERCADONA` e importe 12,40 €; y sobre el texto original devuelve `CHANGLONET, S.L.` y 3,75 €. Una notificación distinta (`Has recibido 5,00 € de Ana`) no coincide.
- Cada mensaje de error del punto 3.
- Plantillas guardadas con el formato anterior siguen decodificándose y coincidiendo igual.
- ViewModel o pantalla: con el caso real, la vista previa se genera y Guardar queda habilitado; la explicación de la regla no contiene un hueco vacío.
