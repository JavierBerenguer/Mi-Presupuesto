# T-042 — Alta de activo a partir del ISIN (OpenFIGI) y búsqueda de criptomonedas (CoinGecko)

- **Estado:** pendiente
- **Rama:** `codex/t-042`
- **Rama base:** `claude/fase-3-mvp` (tras integrar T-041)
- **Depende de:** T-041 (aceptada: `data/quotes/`, `HttpClient`, `SecretStore`, campos `quoteProvider/quoteSymbol/quoteMic`)
- **Riesgo:** medio (red y secretos, reutilizando la infraestructura de T-041). **Sin cambios de Room.**
- **Tipo:** implementación

## Objetivo
`datos-privados/inversiones-requisitos.md`, sección 1:
- Puedo introducir el ISIN de un activo y la app completa automáticamente nombre, ticker, mercado, tipo de activo y divisa de cotización.
- El ISIN (o un identificador igualmente estable) es la clave del activo, no el ticker: el mismo ticker existe en varios mercados.
- Si el ISIN no se puede resolver, puedo introducir los datos a mano (el formulario actual sigue funcionando igual).

Además, como las criptomonedas casi nunca tienen ISIN, para el tipo Criptomoneda se ofrece una búsqueda por nombre o símbolo en CoinGecko.

## Datos verificados por Claude en la documentación oficial (2026-09-28)
- **OpenFIGI:** `POST https://api.openfigi.com/v3/mapping`, cuerpo JSON `[{"idType":"ID_ISIN","idValue":"<ISIN>"}]`, cabecera opcional `X-OPENFIGI-APIKEY: <clave>`, `Content-Type: application/json`. Sin clave: 25 peticiones/minuto; con clave: 25 cada 6 s. Respuesta: un array con un objeto por trabajo, que contiene `data: [ ... ]` con uno o varios listados (`figi`, `name`, `ticker`, `exchCode`, `marketSector`, `securityType`, `securityType2`, `compositeFIGI`, `shareClassFIGI`, `securityDescription`) o `warning: "No identifier found."` si no existe, o `error`. **OpenFIGI no devuelve divisa ni precio.**
- **CoinGecko:** `GET https://api.coingecko.com/api/v3/search?query=<texto>` (disponible en el plan Demo/sin clave), cabecera opcional `x-cg-demo-api-key`. Respuesta: `{"coins": [{"id", "name", "api_symbol", "symbol", "market_cap_rank" (puede ser null), "thumb", "large"}], ...}`.
- **Twelve Data** (ya usado en T-041): `GET /quote?symbol=&mic_code=` con cabecera `Authorization: apikey <clave>`; devuelve `currency`, `close`, `timestamp`, `is_market_open`.

## Decisiones ya cerradas
1. **Sin Room.** Se usan los campos existentes: `isin`, `ticker`, `market`, `currency`, `type`, `name` y los de T-041 (`quoteProvider`, `quoteSymbol`, `quoteMic`).
2. **Validación de ISIN** antes de llamar: 12 caracteres, 2 letras de país + 9 alfanuméricos + dígito de control, con el algoritmo de dígito de control de ISO 6166 (conversión de letras a números y Luhn). Se normaliza a mayúsculas y sin espacios. Si no es válido, error en el campo y no hay llamada de red.
3. **Flujo en el formulario de activo** (alta, y también disponible al editar un activo sin ISIN resuelto):
   - Campo ISIN + botón «Buscar». Llama a OpenFIGI.
   - Si hay varios listados, se muestra una lista para elegir (nombre, ticker, mercado legible, tipo). Si hay uno, se aplica directamente pero se muestra qué se ha rellenado.
   - Al elegir un listado se rellenan: nombre, ticker, mercado (`market` = código de mercado legible, p. ej. «XETRA»), tipo de activo, `quoteProvider = TWELVE_DATA`, `quoteSymbol = ticker` y `quoteMic` según la tabla del punto 5. **Todos los campos quedan editables** antes de guardar.
   - Divisa: si hay clave de Twelve Data, se hace UNA llamada a `/quote` con `symbol` + `mic_code` para obtener la divisa real (y, si la respuesta es válida, se ofrece guardar ese precio como primer precio del activo con `source = PROVEEDOR`, usando `InvestmentRepository.addProviderPrice`). Si no hay clave o falla, se usa la divisa por defecto de la tabla del punto 5 y se indica al usuario que debe confirmarla.
   - Sin conexión, ISIN no encontrado o error: mensaje claro y el formulario sigue permitiendo la entrada manual completa.
4. **Tipo de activo** a partir de OpenFIGI (`securityType` / `securityType2` / `marketSector`, comparación sin distinguir mayúsculas): `Common Stock`, `Depositary Receipt`, `REIT` y equivalentes → `ACCION`; `ETP` y cualquier valor que contenga `ETF` → `ETF`; `Open-End Fund`, `Mutual Fund`, `Fund of Funds` → `FONDO_INVERSION`; si no se reconoce, se deja el tipo actual del formulario y se indica que hay que revisarlo. Para fondos, `quoteProvider = null` (sin proveedor, como en T-041).
5. **Tabla de mercados** (en código, fácil de ampliar, con test): `exchCode` de OpenFIGI → (nombre legible, MIC para Twelve Data, divisa por defecto). Mínimo:
   `US`→(«EE. UU.», null, USD), `UN`→(«NYSE», `XNYS`, USD), `UW`/`UQ`→(«NASDAQ», `XNAS`, USD), `GY`→(«XETRA», `XETR`, EUR), `GR`→(«Fráncfort», `XFRA`, EUR), `SM`→(«Bolsa de Madrid», `XMAD`, EUR), `FP`→(«Euronext París», `XPAR`, EUR), `NA`→(«Euronext Ámsterdam», `XAMS`, EUR), `BB`→(«Euronext Bruselas», `XBRU`, EUR), `IM`→(«Borsa Italiana», `XMIL`, EUR), `PL`→(«Euronext Lisboa», `XLIS`, EUR), `ID`→(«Euronext Dublín», `XDUB`, EUR), `LN`→(«Londres», `XLON`, GBP), `SW`→(«SIX Suiza», `XSWX`, CHF). Un `exchCode` no listado: mercado = el propio código, MIC null, divisa sin sugerir (el usuario la elige). En la lista de listados, ordena primero los mercados de la tabla (europeos antes que el resto) para que sea fácil encontrar el habitual.
6. **ISIN como identidad:** al guardar, si ya existe otro activo no archivado con el mismo ISIN **y** el mismo `quoteMic` (o ambos sin MIC), se avisa y no se crea el duplicado. El mismo ISIN en otro mercado sí se permite (es otro listado).
7. **Criptomonedas:** si el tipo es `CRIPTO`, en lugar de ISIN se muestra un buscador por nombre o símbolo que llama a `/search` de CoinGecko y lista las 10 primeras monedas (nombre, símbolo, posición por capitalización). Al elegir: nombre, ticker = `symbol` en mayúsculas, `quoteProvider = COINGECKO`, `quoteSymbol = id`, mercado = «CoinGecko». La divisa la elige el usuario (por defecto la divisa base de la app).
8. **Clave de OpenFIGI (opcional):** nueva entrada en la sección «Cotizaciones» de Ajustes creada en T-041, mismo tratamiento (`SecretStore`, nunca visible, «Configurada/No configurada»). Sin clave OpenFIGI funciona igual con su límite menor.
9. Implementación en `data/quotes/` reutilizando `HttpClient` (añade `post` con cuerpo JSON si hace falta), `SecretStore` y el patrón de errores tipados de T-041 (`SinConexion`, `NoEncontrado`, `LimiteAlcanzado`, `RespuestaInvalida`, `ClaveInvalida`). Solo HTTPS y solo los dominios `api.openfigi.com`, `api.coingecko.com` y `api.twelvedata.com`. Ninguna clave en URLs, logs, excepciones ni estado de UI.
10. Textos en español; `docs/tasks/COMMON.md` obligatorio (tests con `SettingsStoreRule`; los tests no tienen `AppContainer`).
