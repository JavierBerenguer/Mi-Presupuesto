# T-090 — Cartera: ver el panel completo de Rumbo (solo lectura) dentro de la app

- **Estado:** pendiente
- **Rama:** `codex/t-090-panel-rumbo`
- **Rama base:** `claude/cartera-supabase`
- **Depende de:** T-088 (aceptada) y T-089 (repo de Rumbo; contrato abajo)
- **Riesgo:** medio. Supone mostrar contenido HTML en un WebView y guardar en caché datos personales.
- **Tipo:** implementación

## Objetivo
Desde la pestaña **Cartera**, añadir un botón «Ver panel completo de Rumbo». Abre una pantalla que muestra el panel web de solo lectura que publica el escritorio:
- el HTML se **descarga con la sesión** de Supabase;
- se **guarda en caché** para verlo sin conexión;
- se **muestra en un WebView aislado**, sin acceso a red ni a archivos.

## Contexto y contratos
### Contrato de T-089 (fijo)
- Bucket privado `paneles`, con el objeto en `<user_id>/<perfil_id>.html`.
- **Descarga:** `GET /storage/v1/object/authenticated/paneles/<user_id>/<perfil_id>.html`, con la sesión (`SyncAuthClient.authorized`).
  - 200 devuelve el HTML (`text/html`, UTF-8).
  - 400 o 404 significan que todavía no está publicado.
  - La cabecera `last-modified` indica cuándo se subió.

### Lo que ya hay en la app
- **Sincronización:** `data/sync/` (`SyncRepository`, `SyncAuthClient`, `SyncTransport` / `SupabaseHttpTransport` con validación de host y método).
- **Perfil:** el perfil sincronizado es `settings.syncProfileId`.
- **Usuario:** el `user_id` es el `sub` del JWT de acceso. Si `SyncAuthClient` no lo expone, añade un método que lo lea del token o de `GET /auth/v1/user`. **Nunca registres el token en logs.**
- **Cartera:** `ui/portfolio/PortfolioScreen.kt` y `PortfolioViewModel.kt`.
- **Navegación:** `ui/navigation/MiPatrimonioApp.kt` y `Rutas`.

## Decisiones ya cerradas e invariantes
- **Caché:**
  - el HTML va en `context.noBackupFilesDir/panel_rumbo/<perfil_id>.html`, con sus metadatos (fecha de subida y fecha de descarga);
  - nunca va en almacenamiento externo ni en la copia de seguridad;
  - se borra al **cerrar sesión** (`SyncRepository.signOut`).
- **WebView aislado** (`android.webkit.WebView` en `AndroidView`, sin dependencias nuevas):
  - `javaScriptEnabled = true`, porque el panel lo necesita;
  - `allowFileAccess = false`, `allowContentAccess = false`, `domStorageEnabled = false` y `setGeolocationEnabled(false)`;
  - se carga con `loadDataWithBaseURL(null, html, "text/html", "utf-8", null)`;
  - `shouldInterceptRequest`: **cualquier** petición de red (http, https, ws…) devuelve una respuesta vacía 403. El panel es autocontenido y no debe salir nada;
  - `shouldOverrideUrlLoading`: los enlaces http o https se abren en el navegador externo con `Intent.ACTION_VIEW` y nada se navega dentro del WebView;
  - sin `addJavascriptInterface`;
  - `WebView.setWebContentsDebuggingEnabled` solo en debug.
- **Comportamiento de la pantalla:**
  - abre con la caché si existe;
  - luego intenta descargar y, si llega un HTML distinto, lo sustituye;
  - si no hay red, se queda con la caché y lo indica con un aviso discreto;
  - la cabecera muestra «Actualizado en el escritorio: <fecha>» y tiene un botón de recargar.
- **Estados sin panel:**
  - si no hay sesión o perfil, se muestra un mensaje con un enlace a Sincronización;
  - si no está publicado (404 o 400), se muestra «Abre Mi Patrimonio en el escritorio con la nube activa para publicar el panel».
- **Tamaño:** no se aceptan respuestas de más de 20 MB.
- **Ocultar importes:** no se aplica al panel (es el HTML de Rumbo). Si `hideAmounts` está activo, la pantalla muestra primero un aviso con el botón «Mostrar panel».

## Casos límite a cubrir
- Sin red y sin caché: mensaje y botón de reintentar.
- Sin red y con caché: se muestra la caché con el aviso «sin conexión».
- 401: se aplica el flujo actual de sesión caducada.
- Respuesta de más de 20 MB o que no es HTML: error claro y la caché no se toca.
- Cambio de perfil sincronizado: se usa el archivo de ese perfil.
- Cierre de sesión: la caché se borra.

## Tests obligatorios
- **Repositorio:**
  - ruta exacta de descarga con el `user_id` y el `perfil_id`;
  - 200 → guarda la caché y los metadatos (`last-modified`);
  - 404 o 400 → estado «no publicado»;
  - sin red → devuelve la caché;
  - más de 20 MB → error sin tocar la caché;
  - `signOut` borra la caché.
- **Política de red del WebView**, en una función pura testable:
  - cualquier URL de red queda bloqueada;
  - los enlaces http o https se mandan fuera.
- **Obtención del `user_id`** desde el JWT, sin que el token aparezca en el `toString` ni en los errores.
